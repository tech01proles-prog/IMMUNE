# Immune Empire: Internal Front — MVP Development Plan
# File: 10_MVP_DEVELOPMENT_PLAN.txt

Purpose:
- Turn the design documents into a realistic solo-dev build plan.
- Optimize for Godot 4.x web export to itch.io / CrazyGames.
- Validate the core loop before making large content or art.
- Produce a publishable web alpha in 2–4 weeks.

Main rule:
Make the game fun as a spreadsheet with buttons first. Art, sound and polish amplify a working loop; they do not save a broken one.

---

# 1. MVP Scope Freeze

## 1.1. MVP goal

Create a playable web incremental where the player can:

1. Produce basic nutrients.
2. Convert fuel into ATP.
3. Generate stem cells.
4. Train immune cells.
5. Fight bacterial and viral outbreaks.
6. Collect antigens.
7. Buy simple technologies.
8. Perform first prestige: New Host.
9. Save locally and receive offline progress.
10. Understand the core fantasy within 5 minutes.

## 1.2. MVP resources

Include only these 7 resources:

1. amino_acids
2. glucose
3. lipids
4. micronutrients
5. atp
6. stem_cells
7. antigens

Do not add cytokines, nucleotides, antibodies, hormones, oxygen, iron, zinc, etc. to MVP. They can be data placeholders later, but not visible in early UI.

## 1.3. MVP organs

Include 5 organs:

1. gut_villi
2. mitochondrial_network
3. bone_marrow
4. liver
5. lymph_node

Optional if time allows:
- stomach_acid as simple early barrier.

Do not add full organ map in MVP.

## 1.4. MVP cells

Include 6 cells:

1. neutrophil
2. macrophage
3. dendritic_cell
4. nk_cell
5. b_cell
6. cytotoxic_t

This is enough to teach:
- innate mass defense;
- antigen generation;
- antiviral specialization;
- adaptive precision.

## 1.5. MVP pathogens

Include 3 pathogens:

1. swarm_coccus — bacteria
2. shell_variant — virus
3. thread_bloom — fungus

Optional fourth:
- metabolic_waste — toxin pressure

Do not add parasites, altered self, autoimmune bosses, latent viruses, biofilms or endgame pathogens to MVP.

## 1.6. MVP technologies

Include 12–15 techs:

1. chemotaxis_1
2. oxidative_burst_1
3. granulopoiesis_1
4. glycolytic_flux
5. mitochondrial_biogenesis
6. antigen_presentation_1
7. clonal_expansion_1
8. interferon_pathway
9. complement_cascade
10. mucus_production
11. anti_inflammatory_signals
12. codex_entry
13. antigen_archive
14. trained_immunity
15. vaccine_slot_1 optional

## 1.7. MVP systems

Required:
- fixed-step simulation;
- production;
- defense calculation;
- infection growth/clearing;
- inflammation meter only;
- tech purchase;
- prestige;
- save/load;
- offline progress;
- journal/log;
- basic settings;
- web export.

Not required for MVP:
- full tech web UI with clusters;
- multiple host archetypes;
- vaccines shop;
- achievements;
- microbiome;
- barriers beyond one organ;
- organ sectors;
- rewarded ads;
- CrazyGames SDK;
- localization;
- cloud saves;
- music system;
- complex animations.

# 2. Development Philosophy

## 2.1. Build in layers

Layer 1: Numbers
- resources, costs, income, defense, infection load.

Layer 2: Rules
- bottlenecks, prestige, offline, save validity.

Layer 3: Interface
- readable buttons, bars, tooltips, journal.

Layer 4: Feel
- icons, particles, sounds, pulses, transitions.

Layer 5: Content
- more cells, pathogens, techs, hosts, events.

Do not jump to Layer 4 or 5 before Layer 1–2 are stable.

## 2.2. Data-driven from day one

All content must come from JSON or Resources.

Bad:
    if organ_id == "gut_villi":
        add_amino_acids(0.5 * level)

Good:
    var def = Definitions.organs[organ_id]
    for res_id in def.output:
        rates[res_id] += def.output[res_id] * level

This allows balancing without recompiling logic.

## 2.3. UI is a reader, not the brain

Simulation must run even if UI is hidden. UI only displays state and sends commands:
- buy_organ(id)
- train_cell(id, amount)
- buy_tech(id)
- do_prestige()

No gameplay decisions inside button handlers except input validation.

## 2.4. Save base state only

Save:
- resource amounts;
- organ levels;
- cell counts;
- tech flags;
- infection state;
- meters;
- meta values;
- timestamps.

Do not save:
- derived income;
- total defense;
- modifier cache;
- UI scroll positions optional;
- temporary visual effects.

Rebuild derived state on load.

## 2.5. No game over

MVP should have soft failure:
- infection symptoms reduce production;
- inflammation damages organs;
- resource deficits slow cells;
- prestige remains possible.

Avoid “you died” states. Incremental web players dislike hard loss.

# 3. 14-Day Solo Dev Plan

Assumption:
- 3–6 hours per day.
- You already have Godot installed.
- You can use placeholder rectangles/text.
- Art generation happens in parallel or after core prototype.

## Day 1: Project skeleton and definitions

Goals:
- Create Godot 4 project.
- Set up autoloads.
- Load JSON definitions.
- Implement basic GameState.
- Implement save/load with version.

Tasks:
1. Create project:
   - Main.tscn
   - scripts/autoload/Definitions.gd
   - scripts/autoload/GameState.gd
   - scripts/autoload/SaveManager.gd
   - scripts/utils/SignalBus.gd

2. Add data files:
   - resources.json
   - organs.json
   - cells.json
   - pathogens.json
   - techs.json
   - balance_constants.json

3. Implement Definitions loader:
   - load_json(path)
   - validate ids
   - store dictionaries

4. Implement GameState:
   - default resources
   - empty organs/cells/techs
   - meters
   - helper functions:
     - has_enough(cost)
     - spend(cost)
     - add_resource(id, amount)

5. Implement SaveManager:
   - save_game()
   - load_game()
   - delete_save()
   - SAVE_VERSION
   - normalize missing fields

Acceptance:
- Game starts without errors.
- Can save and reload a basic state.
- JSON definitions load successfully.

Pitfalls:
- Do not connect UI yet.
- Do not make visuals.
- Keep JSON small and valid.

## Day 2: Production loop

Goals:
- Organs produce/consume resources.
- ResourceBar shows amounts and rates.
- Player can buy organs.

Tasks:
1. Create ProductionSystem.gd.
2. Calculate rates from organ levels.
3. Apply simple global multiplier from balance_constants.
4. Add net resources each fixed tick.
5. Create ResourceBar.tscn:
   - icon placeholder
   - name
   - amount
   - rate/s
6. Create OrganPanel.tscn:
   - list organs
   - level
   - cost
   - buy button
   - disabled state

Acceptance:
- Buying gut_villi increases amino_acids and glucose.
- Buying mitochondrial_network consumes glucose/lipids and produces ATP.
- Rates update correctly.
- Save/load preserves organ levels.

Balance check:
- First gut_villi affordable in 30–60 seconds.
- First mitochondria affordable in 1–2 minutes.
- No negative resources unless intended.

---

## Day 3: Cells, upkeep and ATP efficiency

Goals:
- Player can train immune cells.
- Cells consume ATP.
- ATP deficit reduces efficiency.

Tasks:
1. Create CellPanel.tscn.
2. Implement train_cell(id, amount):
   - check cost
   - increase cell count
   - update stats
3. Implement DefenseSystem.recompute():
   - base defense by pathogen type
   - ATP efficiency
   - store derived defense_by_type
4. Implement cell upkeep:
   - required_atp = sum(count * upkeep)
   - efficiency = clamp(atp_income / required_atp, 0.25, 1.0)
5. Show ATP balance in UI.

Acceptance:
- Neutrophil can be trained.
- More cells increase bacteria defense.
- If ATP income is too low, defense efficiency drops.
- UI shows why: “ATP deficit”.

Important:
Cells should not die from upkeep. They become less effective. This is gentler and easier to balance.

---

## Day 4: Infections and first combat loop

Goals:
- Pathogens spawn.
- Infection load grows or shrinks.
- Player clears infection and receives rewards.

Tasks:
1. Create InfectionSystem.gd.
2. Define active infection structure:
   - uid
   - pathogen_id
   - sector optional
   - load
   - growth
   - resistance
   - threshold
   - elapsed
3. Spawn first infection after 30–60 seconds.
4. Tick infections:
   - suppression = defense / (defense + resistance)
   - load += growth * (1 - suppression) * dt
   - load -= clearance * suppression * dt
   - clamp load >= 0
5. On clear:
   - grant rewards
   - add codex entry
   - emit SignalBus.infection_cleared
6. Create ThreatPanel.tscn:
   - active infections
   - load bar
   - pathogen type
   - estimated status

Acceptance:
- swarm_coccus appears.
- Neutrophils/macrophages reduce load.
- Infection can be cleared.
- Reward is granted once.
- Save/load preserves active infection.

Balance target:
- First infection should be beatable with 5–15 neutrophils.
- It should take 30–90 seconds to clear after first army.
- It should not vanish instantly.

# 6. MVP Acceptance Criteria

The MVP is ready when all these are true.

## 6.1. Functional

- New game starts correctly.
- Resources accumulate.
- Organs can be bought and leveled.
- Cells can be trained.
- Infections spawn and can be cleared.
- Rewards are granted.
- Techs can be purchased and apply effects.
- Prestige resets run and preserves meta.
- Save/load works.
- Offline progress works.
- Settings work.
- Web export runs in iframe.

## 6.2. Player comprehension

Within 5 minutes, player can answer:
- What do I produce?
- Why do I need ATP?
- Why do I need stem cells?
- What is an infection?
- Why are viruses different?
- What are antigens for?

Within 15 minutes, player can answer:
- Which branch am I trying?
- What happens if inflammation gets high?
- What does prestige give?
- What is my next short-term goal?

## 6.3. Emotional loop

Player should feel:
- curiosity: “What is this virus doing?”
- agency: “I chose NK over more neutrophils.”
- tension: “My inflammation is rising.”
- reward: “I cleared the outbreak and got antigens.”
- anticipation: “Prestige will make the next run smarter.”

If player only feels “numbers go up”, the immune theme is not strong enough.

# 7. Balance Targets

## 7.1. Early timing

Time | Expected state
0:00–0:30 | See resources, buy first gut_villi
0:30–1:30 | Buy mitochondria, understand ATP
1:30–3:00 | Train first neutrophils
3:00–5:00 | Clear first bacterial infection
5:00–8:00 | Get first antigens, see virus
8:00–12:00 | Unlock NK or dendritic path
12:00–20:00 | Buy first meaningful techs
20:00–40:00 | First prestige available

Adjust if:
- first neutrophil takes >2 minutes;
- first infection takes >3 minutes after army;
- virus appears before player has basic defense;
- prestige takes >60 minutes in MVP.

## 7.2. Resource pacing

MVP target:
- amino_acids and glucose should feel plentiful early.
- ATP should become the first meaningful constraint.
- stem_cells should limit army size.
- antigens should feel rare but attainable.
- lipids/micronutrients should support mid-game organs, not block first 5 minutes.

## 7.3. Defense scaling

Avoid:
- defense growing so fast that infections disappear instantly;
- infections growing so fast that player cannot react.

Good formula:
- pathogen growth scales slowly with run time/prestige;
- player defense scales faster early, then requires specialization;
- resistance prevents infinite one-unit spam.

## 7.4. Inflammation

Target:
- At inflammation 20–40: mild innate bonus, little damage.
- At 50–70: strong innate bonus, noticeable organ efficiency loss.
- At 80+: dangerous, symptoms, possible autoimmune warning.
- Resolution should be possible without resetting.

## 7.5. Prestige

First prestige should grant:
- enough memory to notice improvement;
- not so much that second run is trivial.

MVP suggestion:
- 1 immune_memory = +2% global resource income
or
- permanent upgrades have clear discrete effects.

Avoid exponential prestige in MVP. Keep it simple.

# 10. Godot-Specific Implementation Notes

## 10.1. Fixed step

Use:
    const FIXED_STEP := 0.1

Do not tie simulation to render FPS.

For idle games, 10 Hz is enough. Visuals can interpolate or simply animate separately.

## 10.2. UI throttling

Update UI at 5 Hz:
    const UI_UPDATE_INTERVAL := 0.2

Avoid updating every label every frame.

## 10.3. Object pooling

For cell visuals:
- pre-create 30–50 nodes;
- show/hide based on dominant cell types;
- do not instantiate per cell count.

## 10.4. Web audio

Start audio after first user input.

Godot may require an interaction before AudioStreamPlayer works in browser.

## 10.5. Visibility handling

On web:
- save timestamp when hidden;
- pause expensive visuals;
- on visible, compute offline elapsed once;
- avoid processing both real-time delta and offline delta for same period.

## 10.6. Storage

Primary:
- user://save.json

Fallback:
- JavaScript localStorage via bridge if needed.

Test in private mode and iframe.

## 10.7. Export presets

Use release web export.
Strip unused plugins.
Keep assets compressed.
Avoid huge PNGs.
Prefer SVG icons if possible.
Test final build size.

Target:
- ideally under 50 MB total web build;
- lower is better for CrazyGames/itch.

# 13. Risk Register

## Risk 1: Too complex for casual web players

Symptoms:
- players quit before first antigen;
- too many resources shown;
- tooltips ignored.

Mitigation:
- hide advanced resources;
- first 5 minutes only 4 visible resources;
- strong journal hints;
- one active tutorial objective at a time.

## Risk 2: Biology feels like a lecture

Symptoms:
- players skip text;
- no emotional reaction to pathogens.

Mitigation:
- short punchy messages;
- visual color coding;
- make cells feel like units, not textbook terms;
- use metaphors: swarm, hunters, archivists, furnace.

## Risk 3: One strategy dominates

Symptoms:
- everyone spams neutrophils;
- viruses trivial;
- adaptive branch unused.

Mitigation:
- virus resistance to neutrophils;
- antigen bonus for dendritic/macrophage;
- diversity bonus;
- pathogen modifiers.

## Risk 4: Prestige feels punishing

Symptoms:
- players refuse reset;
- loss aversion.

Mitigation:
- show clear preview;
- preserve codex and vaccines;
- make first memory bonus noticeable;
- allow “soft reset” only when beneficial.

## Risk 5: Web save issues

Symptoms:
- progress lost after refresh;
- iframe storage blocked.

Mitigation:
- test early;
- export/import save;
- warn player if storage unavailable;
- autosave frequently.

## Risk 6: Art delays release

Symptoms:
- generating hundreds of images;
- perfectionism.

Mitigation:
- 30-image MVP asset list;
- palette shader unifies imperfect assets;
- ship alpha with simple icons if needed.

# 22. What Success Looks Like

MVP success is not “everyone loves it.”

MVP success is:

- 10 people play 10 minutes;
- at least 5 understand the core loop;
- at least 3 reach first prestige;
- at least 2 ask for more pathogens/builds;
- you identify the top 3 friction points;
- you know whether to expand or pivot.

If nobody reaches antigens, the problem is pacing/clarity.
If they reach antigens but do not care, the problem is fantasy/reward.
If they care but quit at virus, the problem is difficulty/teaching.
If they prestige but feel nothing, the problem is meta reward.
